# Exercise 2: HTTP Traffic Interception Using Burp Suite

## Objective
To intercept and analyse HTTP requests and responses between a web browser and OWASP Juice Shop using Burp Suite Community Edition.

## Tools Used
- Burp Suite Community Edition
- OWASP Juice Shop
- Chromium-based browser

## Steps Performed
1. Started OWASP Juice Shop on the local machine.
2. Opened Burp Suite and configured its built-in browser.
3. Accessed the Juice Shop application through the Burp browser.
4. Navigated to Proxy → HTTP history.
5. Captured and inspected HTTP requests and responses.
6. Examined request methods, URLs, headers, status codes and response bodies.

## Results
- Captured HTTP GET requests to the local Juice Shop application.
- Observed a `304 Not Modified` response, indicating cache validation.
- Captured a `200 OK` response for a Socket.IO polling request.
- Observed request headers such as Host, User-Agent, Accept and Referer.
- Observed response headers such as Content-Type, Cache-Control and Access-Control-Allow-Origin.

## Conclusion
Successfully intercepted and analysed HTTP traffic generated by OWASP Juice Shop using Burp Suite. The exercise provided practical exposure to HTTP request and response analysis, caching behaviour and application communication.
